# Base AI Agent — 개선 단계 1~3

이 폴더는 원본을 보존한 별도 작업 사본입니다. 적용 범위는 기준선 보존, 대화·출력 요청 구분, 복수 서비스 조사 대상 검증·누락 보완입니다.

## 실행

현재 컴퓨터에서는 원본 가상환경과 .env를 심볼릭 링크로 참조합니다. 키를 코드나 문서에 복사하지 않았습니다. 다른 컴퓨터에 ZIP을 풀었다면 Python 3.11 이상의 가상환경과 requirements.txt 의존성, 본인의 .env를 준비하세요.

이 폴더에서 두 터미널을 열고 각각 실행합니다.

```bash
.venv/bin/python tools/run_local.py backend
```

```bash
.venv/bin/python tools/run_local.py frontend
```

브라우저: http://127.0.0.1:18610

- 백엔드 18110, 프런트엔드 18610을 사용합니다. 이미 이 포트에 서버가 있으면 새로 실행하지 않습니다.
- Ctrl+C로 해당 터미널의 서버만 종료합니다. 기존 8100/8600 서버를 종료하거나 session.db를 지우지 않습니다.
- OpenAI 사용은 과금됩니다. 로컬 기능 검사에는 backend 명령 뒤에 `--model-backend fake`를 붙일 수 있지만 실모델 성능 검증과 구분합니다.

## 변경 내용

1. 요청 경계: POST/SSE에 request_id를 추가하고 모든 이벤트에 같은 ID를 부여합니다. 새 질문은 작업 State를 초기화하고 대화 history만 명시적으로 전달합니다.
2. 대화 저장: 동일 대화의 겹친 요청은 순차 처리하고 user/assistant 한 턴은 하나의 SQLite 트랜잭션으로 저장합니다. 다른 대화 ID의 이력은 가져오지 않습니다.
3. 화면: 대화 ID는 탭의 sessionStorage에 보관합니다. 요청 중 중복 전송을 막고, 다른 요청/이미 끝난 요청의 이벤트를 무시합니다. 재작성 초안은 이전 문자열 뒤에 붙이지 않습니다.
4. 계획 검증: 사용자 질문에 등장하는 지원 서비스의 목록으로 monitoring task를 확정합니다. 누락·중복·요청 범위 밖 대상을 검사하며 analysis task 정책은 유지합니다.
5. 결과 검증: 응답 대상·status·숫자·알림 스키마를 확인합니다. 개별 서비스 실패가 성공한 다른 서비스의 결과를 버리지 않습니다.
6. 보충 조사: 실패·누락 대상만 한 번 추가 조사합니다. 기존 일시적 타임아웃 재시도는 각 조사에서 최대 3회이므로, 지속 타임아웃은 대상당 최대 6회 도구 시도입니다.
7. 미확인 결과: 끝내 지표가 없으면 비교 분석·LLM 권고 생성을 보류하고 실제 확인한 지표와 미확인 대상을 코드로 작성합니다. 0%나 healthy로 대신 채우지 않습니다.

## 테스트

```bash
LANGCHAIN_TRACING_V2=false LANGSMITH_TRACING=false .venv/bin/python -m unittest discover -s tests -v
node --test tests/test_request_ui.cjs
```

Python 테스트는 통제된 planner/도구와 임시 SQLite를 사용합니다. 외부 API를 호출하지 않으며 실제 OpenAI 실행 결과로 제시하지 않습니다. Node 테스트는 화면에서 사용하는 요청 필터와 문자열 누적 로직을 직접 검사합니다.

실모델 응답·SSE·시간·사용량·LangSmith 조회·화면은 evidence/에 별도로 저장합니다. 과거 현상의 혼입 원인을 이번 작업에서 확정한 것은 아닙니다. 기준선에서 재현되지 않았으며, 경계 검사와 회귀 테스트를 강화했습니다.

### 이번 검증 결과

- 통제 테스트: Python 19개, Node 3개 통과.
- OpenAI 실측: 기본 33건과 대화·재시작 확인 5건 완료. 별도 화면 시연 4건을 포함한 LangSmith 완료 기록 42건을 서버에서 재조회했습니다.
- 운영 질문 24건의 조회 대상이 기대값과 모두 일치했습니다. 이는 답변 정답률이 아닙니다. 이번 실모델 실행에는 계획 보완이 필요한 사례가 없어, 누락·추가 대상 보정의 효과는 통제 테스트로 확인했습니다.
- 결과 보기: [실측 보고서](evidence/report.html), [스크린샷](evidence/screenshots/01_scope_checked.png), [최종 검증](evidence/verification.json).
- 실제 브라우저의 대화 전환·이름 회상을 확인했습니다. DevTools에 favicon.ico 404가 1건 있었으며, 이는 탭 아이콘 요청입니다. 해당 화면에서 답변 생성·표시에 실패한 JavaScript 오류는 확인하지 못했습니다.

## 유지한 정책·남은 범위

- 시스템명이 없는 질문과 지원하지 않는 billing-service는 기존 auth-service 폴백을 유지합니다. 추가 질문으로 바꾸는 정책 변경은 이번 범위에 포함하지 않았습니다.
- 서비스명 추출은 지원 이름의 명시적 등장 기준입니다. ‘A는 제외’ 같은 제외 의도와 서비스 별칭 해석은 별도 확장이 필요합니다.
- 동일 대화의 직렬화는 단일 서버 프로세스의 메모리 락입니다. 여러 서버/worker 간 동시성 제어는 검증하지 않았습니다.
- 모니터링은 무작위 변동이 있는 실습 샘플입니다. 실제 장애나 실제 복구를 입증하지 않습니다.
- cost_usd는 가상 단가로 계산하며 실제 청구액이 아닙니다. OpenAI의 AnswerToken은 완성 응답 1개이므로 첫 이벤트 수신시간을 모델 TTFT라고 부르지 않습니다.
- 런북 RAG 검색, 의미·조건 Validator 강화, 사람 승인(HITL)은 다음 단계입니다. 기존 형식 Validator와 런북 선택은 유지합니다.
