# 런북 RAG·근거 및 조건 검수

사용자가 2026-10-20 대화에 제시한 설계를 승인해 구현을 요청했습니다. 단계 1~3 기준 커밋은 4c5bf90이며 기존 ZIP과 evidence는 보존합니다. Desktop 원본·런북 원문·모니터링 원본은 변경하지 않습니다.

## 수용 기준과 순서

1. 검색: 기존 런북 6개를 전체 문서 단위로 Chroma에 저장합니다. OpenAI text-embedding-3-small을 사용하고 원문 해시·모델·인덱스 버전을 기록합니다. 재시작 시 동일 원문을 재임베딩하지 않습니다. 검색 실패·결과 없음·원문 실패를 구분하고 총 최대 2개를 반환합니다. 임계값은 별도 조정 자료에서 정하고 평가 자료와 분리합니다.
2. 연결: 사용자 요청과 서비스별 알림을 검색 입력으로 사용합니다. 검색 ID를 등록 목록과 대조하고 MCP Resource로 원문을 읽어 해시를 확인합니다. 한정된 재검색 후에도 자료가 없으면 확인 불가를 표시합니다. 기존 모니터링 누락 보완·실패 격리는 보존합니다.
3. 근거: 현재 조회값·알림 인용·원인 가설·런북 권고를 구분합니다. 각 관측값에 근거 ID·대상·출처·조회 시각을 붙입니다. 알림의 숫자를 현재 측정값으로 바꾸지 않습니다.
4. 검수: Pydantic 구조화 초안의 근거·대상·수치·조건·조치 상태를 코드로 검사합니다. 조건은 충족/미충족/확인불가입니다. 런북의 원문 절차와 연결하고 없는 지속시간을 만들지 않습니다. 최초 작성 뒤 최대 2회 재작성하며 계속 실패하면 validation_failed로 종료합니다. 강제 통과는 없습니다.
5. 표시: 장애 초안은 검수 전에 AnswerToken으로 전달하지 않습니다. API/SSE에서 검수 상태를 일치시키고 실패는 FinalAnswer 성공 이벤트로 바꾸지 않습니다. 일반 대화 경로는 유지합니다. 실제 조치 도구와 사람 승인은 이번 범위 밖입니다.
6. 증빙: 기존 19개 Python·3개 Node 검사에 새 검색·경계값·오류 주입·POST/SSE 검사를 추가합니다. 고정 자료의 기존/개선 검색을 먼저 비교하고 실제 OpenAI/MCP 실행은 별도로 기록합니다. 수치·정답·성공 로그를 만들지 않습니다.

검사: Python 46개·Node 4개, 조건 반전 오류 주입 검출. 실제 SSE 35건 완료(기본 33건+대화 전환 2건), 운영 질문 대상 24/24건 일치, 조기 초안 노출 0건. LangSmith 그래프 37건 완료를 재조회했습니다(별도 smoke POST·브라우저 시연 포함). 최종 답변의 독립 사람 의미 검수와 저장 스크린샷 확보는 남아 있습니다. 실제 외부 조치는 실행하지 않았습니다.

원본 소스 33개 해시 일치, 로컬/재조회한 그래프 기록의 비밀값 검사 통과, 보고서 링크 검사 및 ZIP CRC 검사 통과를 확인했습니다. 현재 앱은 18120/18620에서 실행 중입니다. 보고서의 표·문장 배치를 Safari에서 직접 확인했습니다.
