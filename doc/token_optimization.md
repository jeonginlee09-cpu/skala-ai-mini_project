# 토큰 최적화와 세 버전 비교

사용자가 승인한 목표는 서비스·수치·근거·조건·실행 여부 검사를 유지하면서 긴 입력과 형식 오류 재작성을 줄이는 것입니다.

## 구현

- `agent/report_selection.py`: 원문/출처/조건은 서버에 보존하고 모델에는 중복 없는 자료와 요청별 A/H 별칭을 전달합니다. 알 수 없는 별칭·임의 필드는 거부합니다.
- OpenAI 모델은 절차와 가설을 고릅니다. 수치와 권고의 종류를 다시 작성하지 않습니다. 코드는 실제 측정 사실을 복사하고 조건 충족 시에만 직접 권고 유형을 붙입니다.
- 완전히 같은 선택·가설·알림은 중복을 정리합니다. 다른 서비스·수치·근거 충돌을 임의 보정하지 않습니다.
- `agent/validator.py`의 기존 서비스·수치·근거·조건 검사는 변경하지 않습니다. 실패 시 재작성 및 최대 시도 후 실패 종료도 유지합니다.
- 별도 모델 분석의 미사용 요약을 없애고 코드가 현재 측정값을 비교합니다. 시계열·배포 자료가 없으므로 인과관계나 공통 원인을 확인했다고 말하지 않습니다.

## 비교 방법

`tools/benchmark_three_versions.py`는 원본 백업, f369c8f, 최적화 커밋을 각각 별도 실험 디렉터리로 만듭니다. 실제 FastAPI/SSE, OpenAI, MCP를 사용하지만 모니터링은 고정한 수업 샘플입니다.

- 질문 11종(이름 등록·회상을 별도 요청으로 계산) × 3회 × 3버전 = 99요청입니다.
- 세 버전의 입력 지표·샘플 시각을 같게 하고 의도적 최초 타임아웃은 모두 끕니다. 원본 소스와 데이터 파일은 변경하지 않습니다.
- 개선본과 최적화본은 동일한 기존 검색 캐시의 독립 사본에서 시작합니다. 실제 캐시 사용량도 기록합니다.
- 실행 순서는 회차별 교차합니다. 모델의 생성 변동과 외부 네트워크 변동을 완전히 통제하지는 못합니다.
- HTTP 요청/응답에서 제공한 prompt/completion/total tokens를 기록합니다. 임베딩과 관련성 판정은 별도로 분류하고 실제 청구액은 추정하지 않습니다.
- 범위 밖 조회는 테스트에서 사전에 정한 대상과 다른 조회를 뜻합니다. 의존 서비스 조사 필요성이 없다고 입증한 지표가 아닙니다.
- Q08의 auth-service 대체 조회 정책은 유지합니다. 처리 완료율·자동 검수 통과율은 최종 답변 정답률이 아닙니다.
- 별도 평가자의 의미·권고 적절성 검수는 남아 있습니다. 원시 응답과 확인 표를 보존합니다.

실행 명령은 다음과 같습니다. OpenAI API 사용량이 발생합니다.

```bash
.venv-rag/bin/python tools/benchmark_three_versions.py --rounds 3
```

결과는 `evidence/optimization_20261021/`에 보존합니다. 이미 결과가 있으면 덮어쓰지 않고 중단합니다. Authorization 헤더·환경 비밀값은 저장하지 않습니다.
