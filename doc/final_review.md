# 최종 제출 기준 점검

평가표의 배점은 기능 구현 30점, 기술 요소 30점, 한계·트레이드오프 20점, 발표 20점이며 동일 입력 Before/After 실측은 10점 보너스입니다. 아래는 충족 근거와 남은 확인 사항을 정리한 자기 점검입니다. 교수자의 점수나 채점 결과가 아닙니다.

## 평가 항목별 확인

| 평가 항목 | 현재 준비 상태 | 확인 근거 | 남은 확인 |
|---|---|---|---|
| 기능 구현 완성도 / 30 | 코드와 자동 검사 완료, 실제 API 결과는 최종 비교표 참조 | 서비스 범위 대조, RAG, ID 선택·코드 검수, 선택적 Reviewer, 후속 대상 연결·새 조회 | 독립 평가자의 답변 의미·권고 적절성 채점 |
| Before/After / 보너스 10 | 같은 입력의 새 비교와 제공자 사용량·추적 기록을 보존 | [최종 수치](final_comparison.md), [집계](final_comparison.csv), [실제 답변](final_execution_examples.json) | 실제 청구액과 통계적 유의성은 미측정 |
| 기술 요소 / 30 | 필요한 기능에 적용하거나 기존 기반을 유지 | 아래 기술 요소 표와 코드 위치 | 단순 기술 이름 나열로 가점을 단정하지 않음 |
| 한계·트레이드오프 / 20 | 지연·토큰·오판·자료 범위·캐시 조건을 설명 | 최종 비교표, README 한계, 발표 자료 | 실서비스·문서 대규모 확장의 성능은 미확인 |
| PPT 작성 및 발표 / 20 | [PPT](../output/AI_Agent_개선_최종발표.pptx)와 [발표문](presentation_script.md) 준비 | 문제, 개선 코드, Before/After, 한계·개선 순서 | 실제 발표와 5분 리허설은 사용자가 진행해야 함 |

## 기술 요소가 실제로 연결된 위치

| 기술 | 현재 적용 | 근거 파일 | 과장하지 않을 부분 |
|---|---|---|---|
| Multi-Agent | Writer와 별도 Reviewer의 지시문·출력 계약·조건부 환류 | `agent/semantic_review.py`, `agent/openai_llm.py`, `agent/graph.py` | 모든 노드가 Agent가 아니며 Reviewer는 새 외부 사실을 조사하지 않음 |
| MCP | 기존 별도 stdio 프로세스의 모니터링 Tool·런북 Resource·운영 Prompt 사용 | `agent/mcp_client.py`, `mcp_server.py`, `agent/graph.py` | 새 독립 HTTP 마이크로서비스로 분리했다고 표현하지 않음 |
| RAG | 임베딩·Chroma 순위·관련성 선택·인용 확인·원문 해시 확인 | `agent/embeddings.py`, `runbook_retriever.py`, `relevance.py` | 여섯 문서 전체를 관련성 후보에 주므로 대규모 Vector DB 우위를 입증한 비교가 아님 |
| 의존성 주입 | lifespan에서 만든 객체를 SupervisorDeps로 전달 | `server.py`, `agent/deps.py` | 원본에도 있던 기반을 유지함 |
| LangSmith | 실행 노드·모델 호출의 계층 추적과 실제 Run 재조회 | `@traceable`, `tools/report_final_alignment.py` | 대시보드 기록이 답변 정확도 자체를 보장하지 않음 |
| 모듈화 | 대상 연결, 검색, 근거, 조건, ID 선택, 검토, 세션을 분리 | `agent/request_context.py`, `target_scope.py`, `evidence.py`, `validator.py`, `report_selection.py`, `semantic_review.py` | 모듈 수 자체를 개선 효과로 제시하지 않음 |
| 단위·회귀 검사 | 통제 도구·모델로 실패 조건 재현, 서버·UI 기존 회귀 검사 유지 | `tests/` | 가짜 모델 통과를 실제 모델 성공 로그로 쓰지 않음 |

## 검증 방법과 실패 기록

- Python 전체 검사 **90개**와 기존 화면 처리 검사 **5개**를 실행했습니다. 새 스트리밍 전용 검사나 첫 토큰 시간 지표는 추가하지 않았습니다.
- 세 증상, 명시한 새 대상 우선, 모호한 단수 대상, 다른 세션의 정보 혼입 방지, 과거 수치 미사용을 검사했습니다.
- 추가 실제 실행의 첫 시도에서 F06은 대상을 연결했지만 라우터가 `chat`으로 분류했습니다. 새 조회 없이 이전 수치로 답했으므로 기능 성공으로 인정하지 않았습니다.
- 해당 실패는 `evidence/final_alignment_20261021/`과 [작은 실패·수정 사례](followup_failure_and_fix.json)에 보존했습니다. 일반 대화로 오분류하는 통제 모델로 회귀 테스트를 먼저 실패시킨 뒤, 연결된 운영 후속 질문의 새 조회를 보장하는 가드를 추가했습니다. 최종 수정 소스는 `69d58eb`입니다.
- 이후 `evidence/final_alignment_verified_20261021/`에서 원본과 최종 수정본을 처음부터 다시 비교했습니다. 준비·추가 기능 입력을 본 비교 66건에 섞지 않습니다. 최종 본 비교는 양쪽 모두 33/33건 완료했고, 별도 새 기능 검사는 10/10건을 통과했습니다. 준비 8건을 포함한 LangSmith 그래프 84건을 재조회했습니다. [기계가 집계한 최종 요약](final_measurement_summary.json)을 확인합니다.
- Provider usage, 고정 수업 샘플, 런북 원문, 동결한 실행 사본의 해시를 대조합니다. 실패·보류도 분모에서 빼지 않습니다.

## 삭제·이동·보존

- 삭제: 운영 그래프에서 호출되지 않는 `_extract_system_name()`과 관련 미사용 import.
- 이동: 옛 키워드 분류기는 비교에 필요하므로 `tools/baseline_runbook_selection.py`로 이동했습니다. 운영 RAG 경로에서는 호출하지 않습니다.
- 보존: 원본 과제, 과거 실측·실패 실행, v1 토글, fake/Ollama 어댑터, 기존 단위·화면 검사는 유지했습니다. 구버전 문서는 과거 자료임을 표시했습니다.
- 제출 제외: `.env`, 가상환경, 대화 DB, 검색 캐시, 원시 요청·응답·제공자 로그는 `.gitignore` 대상으로 유지합니다. 작고 검토 가능한 집계·예시는 `doc/`, 비교 입력은 `data/`에 포함합니다.

## 아직 구현·확인하지 않은 것

사람 승인(HITL), 실제 조치 실행, 운영 데이터 수집, 실제 비용 청구액, 서버 재시작을 포함한 최신 버전의 실제 이름 회상 검증, 독립적인 의미 정답률, 모든 한국어 지시 표현, 다중 worker 운영 성능은 이번 검증으로 완료했다고 주장하지 않습니다.

기존 `billing-service`의 `auth-service` 대체 정책도 남았습니다. 요청 범위 일치 지표에서 이 정책과 일치하더라도 billing-service의 상태를 알아낸 것이 아닙니다. 다음 개선에서는 미지원 대상 확인 안내로 바꾸는 것이 적절합니다.
