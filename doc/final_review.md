## 신규 기능으로 소개하지 않는 기존 동작

복수 서비스 계획, 대상 이름 정규화와 중복 제거, SQLite 대화 저장과 이름 회상, 요청별 새 그래프 입력, 일반 대화 라우팅, 병렬 조회, TimeoutError 재시도, 재계획, 작성 횟수 제한, SSE·최종 문자열 표시, AI와 코드의 역할 분리는 원본에 있었습니다.

최종 차이는 부분 계획 누락·실제 지표 누락 보완, 런북 선택 방식, 답변의 참조·조건 검사, 별도 Reviewer, 운영 지시 대상 연결, 요청 ID와 저장 경계의 보완입니다. 원본을 기능이 전혀 없던 시스템으로 묘사하지 않습니다.

## 검증과 실측의 범위

- 최종 제품의 Python 90개·기존 화면 처리 5개 검사 기록을 확인했습니다. 새 스트리밍 전용 검사나 첫 토큰 지표는 추가하지 않았습니다.
- 실제 본 비교는 원본·최종본 각각 33/33건 완료했습니다. 추가 기능 10/10건과 검색 준비 8건은 본 비교의 시간·토큰에 섞지 않았습니다.
- 준비 실행을 포함한 LangSmith 그래프 84건, provider usage, 모니터링 샘플·런북·동결 소스 해시를 대조했습니다. [집계 요약](final_measurement_summary.json)을 확인할 수 있습니다.
- 평균 시간은 4.207초→3.246초이며 모델 총 토큰은 29,671개→74,252개입니다. 근거·조건·Reviewer 입력이 추가되어 토큰은 늘었습니다. 각 변경의 개별 성능 기여는 분리하지 않았습니다.
- 조회 대상 정책 일치는 양쪽 24/24건이고 누락도 양쪽 0건입니다. 이번 실행에서 조회 정확도가 개선됐다고 주장하지 않습니다. 정책에는 미지원 billing-service의 auth-service 대체가 포함됩니다.
- 최종본의 추가 사례에서 세 증상 근거와 후속 대상 연결을 확인했습니다. 그 입력의 원본 결과를 함께 측정하지 않았으므로 기능 동작 확인으로만 설명합니다.
- 이번 작업은 문서·PPT 수정입니다. 운영 코드를 바꾸거나 유료 API 실험을 다시 실행하지 않았습니다. 실제 수치와 원시 기록은 그대로 보존했습니다.
